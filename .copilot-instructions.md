Toujours scoper toute lecture et toute mutation par project_id.
Ne jamais faire de query globale métier sans filtre projet explicite.
Toute mutation métier doit passer par emitEvent() ou une couche dérivée event-driven.
Les tables append-only (project_events, audit_logs, activity_logs) ne doivent jamais être mises à jour ni supprimées côté app.
Toute UI doit être context-aware : projet courant, rôle courant, état réseau.
Toute feature doit rester offline-first : fallback queue si réseau absent.
Toute query React Query doit utiliser une clé scopée incluant projectId quand la donnée est projet-dépendante.
Les permissions viennent de project_members et doivent être évaluées avant affichage ou mutation.
Préférer des migrations SQL additives et éviter les breaking changes sur le schéma existant.
Quand une projection UI est dérivée de l'event store, ne pas utiliser la table d'état comme source de vérité.
